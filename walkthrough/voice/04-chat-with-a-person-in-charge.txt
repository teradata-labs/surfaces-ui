Now the agent side. A chat reply here isn't a picture of a chart. It's the real component, querying real data, and every message the agent sends is checked against a catalog first. Anything not in the catalog simply isn't drawn. Each component also declares the events it sends back, and what they carry. A decision card sends the choice, and a sequel proposal sends the sequel. If an agent says what it expects and an event doesn't match, it's refused before it leaves the page. And when a person changes a filter or a sort by hand, the agent sees that on its next turn. When an agent wants to do something that changes data, the turn pauses. A person sees exactly what will run, can edit it, gives a reason, and types "confirm". The server checks that answer before anything happens, and a receipt shows what ran.
