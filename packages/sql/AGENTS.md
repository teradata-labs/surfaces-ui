# `packages/sql`

Agent notes for this folder. The rules that hold everywhere are in the root [AGENTS.md](../../AGENTS.md). What you learn about this folder goes here.

**MySQL** (`SqlDialect.MYSQL`, for MySQL and MariaDB) differs in four ways, all in `rewrite.ts` and `guard.ts`. Names go in backticks: MySQL reads a name in double quotes as text unless a session setting says otherwise, and everything this library and its components write puts names in double quotes, so `mysqlNames` rewrites them, in the base query before it is parsed and in the finished statement; it follows that on a MySQL source text is written in single quotes. There is no `NULLS FIRST` or `LAST`, so a sort is preceded by one on whether the value is null. There is no `DATE_TRUNC` (`MYSQL_GRAIN`), and no median or percentile, which are refused with the reason and never approximated. A backslash in a string is an escape, so `LIKE`'s escape character is written doubled and `blankLiterals(sql, true)` reads strings MySQL's way. Run on MariaDB 10.11 through its MCP server; not on MySQL itself. Pipeline checks (`checks.ts`) have no MySQL form.

**SQL Server, Snowflake, BigQuery, Databricks and Oracle** are dialects too (`SqlDialect.SQLSERVER` and the rest). **None has been run on a real system**: every statement the tests write is checked to parse in its dialect (`parses`), which is what the Teradata forms had before a system was reached, and no more. What differs, all in `rewrite.ts`: SQL Server and Oracle page with `OFFSET … ROWS FETCH NEXT … ROWS ONLY` (SQL Server only after an `ORDER BY`, so a page with no sort gets `ORDER BY (SELECT NULL)`); Oracle takes no `AS` before a derived table's alias (`named`); BigQuery and Databricks write names in backticks as MySQL does (`BACKTICKS`); a `LIKE` escape is written doubled where a backslash in a string is an escape (`BACKSLASHES`), and left out on BigQuery, which has no `ESCAPE`; time buckets are `SQLSERVER_GRAIN` (counted from day 0, a Monday, because `DATEDIFF(week)` turns over on a Sunday), `TIMESTAMP_TRUNC` over a cast on BigQuery, and `TRUNC` with a format on Oracle; a median or percentile is the database's approximate aggregate on SQL Server (2022 or later) and BigQuery, whose exact forms are window functions, and `PERCENTILE` on Databricks (`QUANTILE`); a division is cast to each dialect's float (`FLOAT`). Known gaps: on Oracle a date sent as text compares with a date column only if the session's date format is ISO; on Snowflake and Oracle a name is matched in the case the database holds it, which is upper case for a name created without quotes. No engine uses these dialects yet: `@surfaces-ui/engine-mcp` needs, for each, a way to get a result's types.

| Path | What it is |
|---|---|
| `packages/sql` | `rewriteQuery` / `countQuery`: turns a `ViewQuery` into dialect SQL with bound parameters (DuckDB `LIMIT/OFFSET`, Teradata `TOP` / `QUALIFY ROW_NUMBER()`), plus read-only checks. `columnsQuery` (a base query's columns, no rows) and `withoutMissingFilters` (drops filters on columns a view's rows lack, with a `FILTER_COLUMN_MISSING` notice). Parser: `@polyglot-sql/sdk`, used only here. |
