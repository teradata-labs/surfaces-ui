# `packages/engine-teradata`

Agent notes for this folder. The rules that hold everywhere are in the root [AGENTS.md](../../AGENTS.md). What you learn about this folder goes here.

| Path | What it is |
|---|---|
| `packages/engine-teradata` | Teradata through Teradata Query Service (its REST API) over `fetch`, or through a driver connection the consumer supplies (`driverClient`); this repo never installs or imports a Teradata driver. Read-only: no kept results, pipelines, time travel or error positions, and the database user should hold SELECT rights only, since Teradata has no read-only session. Config: `{ id, engine: "teradata", baseUrl, system, user, secret, database? }`; the password or JWT is read from `<SECRET>_PASSWORD` or `<SECRET>_TOKEN` and never appears in config or an error. Values are bound through the transport (`params`), never written into a statement. The catalog comes from `DBC.DatabasesV`, `TablesV`, `ColumnsV` and `IndicesV` (the primary index is reported as `primary_key`); table listings are searched and paged by Teradata (`Engine.pagesTables`) and capped at 1000 when no page size is given. The session is set to UTC with the query band `ApplicationName=surfaces-ui`; one explicit session runs one request at a time (`session: "implicit"` runs them side by side but uses the user's own time zone and default database). A result over 250,000 rows is an error, not a short result, so a large CSV export fails on this engine. DECIMAL is exact only when the transport reports precision and scale. `WRITE_NOS`, `SCRIPT` and `FOREIGN TABLE` are refused inside a query. The dev server takes a driver source as `{ id, engine: "teradata", transport: "driver", connect, address?, database? }`, where `connect` opens the consumer's own driver connection; the repo's `surfaces.config.ts` builds one from `teradatasql` installed outside the repo (`SURFACES_TERADATA_DRIVER`, default `~/.cache/surfaces/teradata-driver`) when `SURFACES_TERADATA_HOST` is set, with `SURFACES_TERADATA_USER`, `TERADATA_PASSWORD` and an optional `SURFACES_TERADATA_DATABASE`. With `column_type` on, the driver puts the type after a tab in each column name, which `driverClient` splits. Teradata's own error number reaches the client as `QueryError.engineCode`. `driverClient` reads a result with the cursor's `fetchmany` when it has one, a batch at a time with a pause between: the `teradatasql` driver's `fetchall` reads without yielding and held the whole dev server still for about 20 seconds on a large dictionary read. A listing that names no database covers the engine's `databases` (default: the default database), and search and agent context are built from those; `surfaces.config.ts` reads them from `SURFACES_TERADATA_DATABASES` (default: the default database and the user's own). Describing several tables of one database in quick succession reads that database's dictionary whole and keeps it five minutes, so an index build does not ask per table. Discovery's `skipRowCounts` lists sources whose tables are indexed without counting rows (Teradata here); the dev server builds the index in the background at start, which on a 500-table Teradata database with the local embedder took about five minutes, most of it embedding. Descriptions and certifications are still keyed by table name without its database, so two tables of one name in different databases share them. `packages/dev-server/src/teradata.test.ts` runs live when `SURFACES_TEST_TERADATA` (Query Service) or `SURFACES_TEST_TERADATA_HOST` (driver) is set. Query Service, unverified: request field spelling (`keyStyle`), the `/systems/` path, type names in replies, session expiry, `EXPLAIN` with bound values, the DBC column names used, and the driver connection's shape. |
