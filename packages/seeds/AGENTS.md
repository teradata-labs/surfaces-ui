# `packages/seeds`

Agent notes for this folder. The rules that hold everywhere are in the root [AGENTS.md](../../AGENTS.md). What you learn about this folder goes here.

| Path | What it is |
|---|---|
| `packages/seeds` | Six synthetic industry models (retail, healthcare, fraud, telco, transportation, manufacturing): tables with keys and descriptions, planted data problems, forms, pipelines, starter pages and written conversations (`conversations`; a model with none of its own gets "What is in the … data?" written from its own dashboard spec by `overviewConversation`, so the Sample analysis page never shows another model's data; retail has "Which products and stores drive our refunds?", five joined tables answered as a diagram, description cards, numbers, charts, a table, the pipeline graph and a dashboard, with every query tested against the seed and the join checked to keep each return once). Two conversations go end to end, connecting a source through to a dashboard: retail's "From the lake to a refund dashboard" (`retail-lifecycle.ts`: a connect plan with the credential named only, the source in an `ObjectBrowser`, a cleaning plan and a personal data review with counts from the engine, the pipeline graph, its quality rule and the live `PipelineView`, a `SemanticModelEditor` proposing `order_lines` from five tables on the join diagram, a `ReportBuilder` over the model's fields and a filtered dashboard) and telco's "Who is leaving, and why?" (`telco-lifecycle.ts`: two connections, personal data, a `ModelDiagram` with `rowsFrom` showing which tables repeat a subscriber, cleaning and the churn pipeline, a model written as a query, a report and a dashboard). Every count their text states is a constant (`RETAIL_FACTS`, `TELCO_FACTS`) checked against the seed by `seeds.test.ts`, and their model rows (`ORDER_LINES`, `SUBSCRIBER_ROWS`) are checked to keep one row per line or subscriber. `titledChart` puts a heading over a chart, which the catalog's `Chart` does not draw itself. Parquet in `data/`. `seeds: true` (or no config) serves them from the dev server. |
