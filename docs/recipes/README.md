# Recipes

Each recipe is code that runs in CI: the source shown is the source tested in `apps/recipes`. Generated by `pnpm docs:gen`; do not edit by hand.

- [A chat for analytics users](analytics-chat.md): `AnalyticsChat` is a chat for people who work with data. The conversation is always there; everything else appears only when you pass its prop:
- [Ask a person before a query runs](approval-before-sql.md): An agent that wants to run SQL shows it to a person first. The person can allow it, deny it, or edit it and allow their version. Only what they allowed runs, and only after the agent has checked the answer.
- [A dashboard a person can arrange](arrange-dashboard.md): Any page drawn from a `PageDocument` can offer Arrange: a person drags a component by its bar to before or after another, to either side of one to put the two side by side, or onto the end of a container; drags the handle under it to change its height, or at its right edge to change widths. Every drag has a keyboard form (the bar's arrows, arrow keys on the handles), and drags use pointer events, so they work by touch and pen.
- [Chat with Claude over your own data](claude-chat.md): Run Claude on your server as the chat's agent. It sees your tables through a `list_tables` tool, draws charts, tables and numbers from the catalog, and those components run their SQL through your read-only data source. The browser talks only to your server, so the API key never reaches it.
- [Connect Postgres, Teradata and S3](connect-sources.md): One `surfaces.config.ts` that reads a Postgres database, a Delta table in S3 and a Teradata system, all read-only, with every credential named by a secret and read from the server's environment. A source that cannot be reached does not stop the server; `testSource` says what is wrong.
- [A dashboard from SQL with cross-filtering](cross-filter-dashboard.md): One query feeds headline numbers, two bar charts and a table. Clicking a bar filters every other view, each filter can be removed with a button, and every view asks the engine for its own summary, so nothing is filtered or grouped in the browser.
- [A form that writes back](form-writeback.md): A page with a `Form` whose submissions the dev server checks and stores, then serves back as a read-only table. The server owns the form: its fields, their rules and where submissions go. The browser sends a form id and values, never SQL, a table or a path.
- [Show live views in Claude Desktop (MCP Apps)](mcp-claude-desktop.md): Give an MCP host such as Claude Desktop tools that show live tables, charts, pivots, an SQL editor and agent-drawn surfaces over your data. The model calls a tool; the host shows the Surfaces app page, which fetches only the rows on screen. Queries stay on your machine and run read-only.
- [Embed in a Next.js app](nextjs-embed.md): Put a query result into a page of an existing Next.js app, themed only in its own region, talking to your data server from the browser. The component is ordinary React with `"use client"` at the top; the page loads it in the browser only.
- [Bring your own backend (DataSource)](own-datasource.md): Every component reads data through one interface, `DataSource`. If you already have a query API, write an adapter for it and install no data-layer package: no engine, no dev server, no Connect client. This recipe adapts a plain HTTP API that answers with Arrow, and adds a small wrapper that limits which sources a page can reach.
