  <action>
Investigate styling issues in bundled HTML by comparing development vs production environments:

1. **Analyze current bundle** to identify CSS issues:
   - Extract first 500 lines of built bundle: `head -500 packages/components/dist/apps/json-render-cdn.html > /tmp/bundle-head.txt`
   - Search for Tailwind classes: `grep -o "text-\|bg-\|p-\|m-\|flex\|grid" /tmp/bundle-head.txt | head -20`
   - Search for CSS custom properties: `grep -o "\-\-[a-z-]*:" /tmp/bundle-head.txt | head -20`
   - Check if Tailwind CSS is inlined or referenced

2. **Root cause analysis** of likely issues:
   - **Issue A**: Tailwind CSS may not be inlined in bundle (vite-plugin-singlefile limitation)
   - **Issue B**: CSS custom properties from tokens.css may not be included
   - **Issue C**: Tailwind purging may have removed necessary utility classes
   - **Issue D**: Theme system CSS vars may not be applied to document root

3. **Implement fixes** based on root cause:

   **Fix A - Ensure Tailwind CSS is inlined**:
   - Update `json-render-cdn.html` to include critical Tailwind base styles in `<head>`
   - Add style block with Tailwind directives: `@tailwind base; @tailwind components; @tailwind utilities;`
   - Or add link to Tailwind CDN as fallback: `<link href="https://cdn.jsdelivr.net/npm/tailwindcss@3.4.0/dist/tailwind.min.css" rel="stylesheet">`

   **Fix B - Inline CSS custom properties**:
   - Add tokens.css content directly to HTML `<head>` style block
   - Include all CSS variables from `:root` selector (--background, --foreground, --primary, etc.)
   - Include both light and dark mode variants (.dark class overrides)

   **Fix C - Verify Tailwind config for bundle builds**:
   - Check `vite.config.apps.ts` PostCSS configuration
   - Ensure Tailwind processes app HTML files in content array
   - Add explicit content path: `./src/apps/**/*.{html,tsx,jsx}`

   **Fix D - Ensure FOUC script sets dark class before React**:
   - Verify FOUC prevention script runs before any styles load
   - Script already exists in HTML but verify it executes early enough

4. **Preferred solution** (based on vite-plugin-singlefile best practices):
   - Inline critical CSS (tokens + Tailwind base/utilities) in HTML `<head>`
   - Let Vite bundle remaining component-specific CSS
   - Avoid external CDN links (breaks offline/file:// protocol usage)

5. **Update vite.config.apps.ts if needed** to ensure CSS inlining:
   - Verify PostCSS plugin chain includes Tailwind
   - Check build.cssCodeSplit setting (should be false for single-file bundles)
   - Ensure all CSS imports are processed and inlined
